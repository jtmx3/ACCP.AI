# عقد ربط ACCP.AI مع مشروع ACCP على C#/.NET

**الحالة:** توثيق للواجهات الموجودة في نموذج Python فقط. لم يُفحص مستودع C# الحالي ولم يُنفّذ الربط الفعلي؛ يجب مراجعة المشروع ونموذج صلاحياته قبل التنفيذ.

## حدود المسؤولية

يوفر ACCP.AI مقابلة محلية تحفظ إفادات المستخدم كمسودة منظّمة مع الاقتباسات ومصادرها، ثم تتيح المراجعة والتصحيح والتأكيد. لا ينشئ هذا التأكيد بلاغًا رسميًا، ولا يثبت صحة الوقائع، ولا يرسلها إلى جهة خارجية. على تطبيق .NET أن يربط جلسة Python بحساب ACCP وبلاغه، وأن يفرض صلاحيات المشروع قبل عرض التقرير أو حفظه.

لا تُرسل إلى Python كامل سجل المستخدم أو تفاصيل ACCP غير اللازمة. الجسم المرسل في الرسائل هو النص الذي أدلى به المستخدم فقط، وأي سياق سابق للنموذج الخارجي يحتاج موافقة صريحة منفصلة. لا تُفعّل `allow_context_extraction` إلا إذا أُجيز هذا الغرض للمستخدم والبلاغ المحددين.

## المصادقة وربط الجلسة

1. ينشئ خادم .NET جلسة عبر `POST /api/sessions`. يعيد Python `session.session_id` ورمز `token` سريًا مرة واحدة.
2. يحفظ .NET الربط في مخزن محمي، مثل `{AccpUserId, AccpIncidentId, PythonSessionId, ProtectedPythonToken}`. يُشفّر الرمز بخدمة حماية الأسرار المناسبة؛ لا يرسل إلى المتصفح، ولا يسجل في logs أو analytics، ولا يُخزن في JavaScript أو قاعدة بيانات العميل.
3. يمرر خادم .NET الرمز إلى Python في الترويسة `X-Case-Token` عند كل قراءة أو تعديل. يحفظ .NET معرّف آخر `revision` الذي عرضه للمستخدم.
4. لا يمكن استعادة الرمز من Python. إذا فُقد، لا تتجاوز ذلك بإنشاء جلسة بديلة تلقائيًا أو حذف الجلسة القديمة؛ استخدم إجراء دعم/استرداد يقرره مالك المشروع.

هذه البنية توصية ربط وليست تنفيذًا داخل C#.

## واجهات الجلسة

| العملية | الواجهة | الغرض |
|---|---|---|
| إنشاء | `POST /api/sessions` | إنشاء مسودة وإرجاع `session`, `token`, و`token_notice`. لا يتطلب جسمًا. |
| قراءة | `GET /api/sessions/{session_id}` | جلب الوقائع والرسائل والمرحلة والمراجعة والتقرير المحسوب. عملية قراءة، لا تحفظ تعديلًا. |
| رسالة | `POST /api/sessions/{session_id}/messages` | إرسال جواب أو سؤال أو مراجعة/تصحيح بصيغة رسالة. |
| استكمال | `POST /api/sessions/{session_id}/resume` | استئناف الجلسة المحفوظة باستخدام `expected_revision`. يعيد سؤال المقابلة أو توضيح المنصة المعلّق. |
| تأكيد | `POST /api/sessions/{session_id}/confirm` | تأكيد إصدار الملخص الحالي بعد المراجعة؛ لا يرسل بلاغًا. |
| توضيح تعارض زمني | `POST /api/sessions/{session_id}/resolve-temporal-conflict` | اختيار بديل زمني محفوظ حرفيًا مع سبب يقدمه المراجع؛ يحفظ سجل التعارض ولا يؤكد الملخص. |
| تنزيل Markdown | `GET /api/sessions/{session_id}/report.md` | تقرير المراجعة بصيغة Markdown. |
| تنزيل JSON | `GET /api/sessions/{session_id}/report.json` | التقرير المنظم. |
| سجل التدقيق | `GET /api/sessions/{session_id}/audit` | أحداث التغيير المسجلة للجلسة. |

كل واجهات الجلسة باستثناء الإنشاء تتطلب `X-Case-Token`. لا تُعرّض هذه الواجهات مباشرة لمتصفح المستخدم إذا كان ذلك سيفضح الرمز؛ اجعل .NET وسيطًا مصادقًا عليه.

### إرسال رسالة وموافقة النموذج

مثال جسم الرسالة:

```json
{
  "expected_revision": 7,
  "text": "النص الذي كتبه المستخدم",
  "kind": "answer",
  "allow_external": false,
  "allow_external_extraction": false,
  "allow_context_extraction": false
}
```

`kind` يقبل `answer` أو `question`. الافتراضات الثلاثة للموافقة `false`. يجوز السماح بصياغة جواب من مقتطفات المصادر عبر `allow_external`، أو باستخراج رسالة المستخدم عبر `allow_external_extraction`. لا يرسل السياق السابق إلا إذا كان استخراج النموذج مسموحًا وأُرسل `allow_context_extraction: true`. لا تعتبر مجرد إعداد Ollama أو المزود موافقة على نقل النص.

تحتوي نتيجة الرسالة على `session`, `report`, `message_plan`, `provider_call`, و`provider_calls` و`timings` بحسب المسار. التوجيه المقبول، والاستخراج المقبول، والرد المستند إلى مصادر، والرجوع إلى القواعد إشارات منفصلة؛ لا تعرض `answer` أو JSON صالح وحده على أنه نجاح استخراج.

### مقاييس زمن الدور وآثار استدعاء النموذج

يعيد `timings` أجزاءً من زمن طلب API بالمللي ثانية: `request_preflight_ms` لفحوص الطلب السابقة للتغيير، و`message_understanding_ms` لفهم أهداف الرسالة، و`retrieval_ms` لاسترجاع المصادر، و`answer_generation_ms` لتوليد الرد الإرشادي، و`save_ms` للحفظ، و`total_ms` للزمن الكلي المقاس داخل التطبيق. قد تكون مراحل غير مطلوبة صفرًا أو غير منفذة. `provider_preflight_ms` يقبل `null`، وتوضح `provider_preflight_performed` إن كان فحص اتصال منفصل قد حدث؛ لا تستنتج نجاح الاتصال من قياسه أو من الإعداد.

`provider_calls` قائمة مرتبة حسب تسلسل الاستدعاءات داخل الدور، وتحمل `purpose` مثل `interview_extraction` أو `grounded_answer`؛ أما فحص التوليد الثابت فيستخدم `provider_generation_test`. وتتضمن العناصر `attempted`, `status`, `result_accepted`, `fallback_used`, `latency_ms`, `failure_code`, `provider`, و`model` بحسب المسار. قد تظهر معلومات محدودة عن موافقة السياق وحجمه، وتظهر أهداف الرسالة المقبولة عند انطباقها. `provider_call` هو ملخص/أثر الاستدعاء الأخير؛ لا تستخدمه بدل القائمة عند وجود أكثر من استدعاء. قد يحتوي أثر آخر استدعاء على `turn_any_result_accepted` و`turn_fallback_used`، وهما يصفان الدور ككل، بينما `result_accepted` و`fallback_used` في كل عنصر يصفان ذلك الاستدعاء.

الأزمنة داخل التطبيق تقريبية، ولا تشمل زمن الشبكة بين .NET وPython أو واجهة المستخدم. اجمع `total_ms` مع قياس العميل إذا كان مطلوبًا زمن طرف إلى طرف، ولا تجمع أزمنة المراحل آليًا لأن أجزاء التنفيذ قد تتداخل أو لا تعمل في كل مسار. آثار المزود لا تحتوي نص الطلب أو الاستجابة الخام أو مفاتيح الجلسة أو بيانات الاعتماد؛ لا تضفها إلى سجلات .NET.

### المراجعة والتصحيح والتأكيد

المراجعة جزء من الحوار: يعرض .NET التقرير الحالي، ويعيد تصحيح المستخدم أو طلب الإضافة إلى `/messages` مع `expected_revision` الحالي. يقرأ التطبيق التقرير مرة أخرى قبل اعتماد التعديل. تُبطل أي وقائع متغيرة تأكيد النسخة السابقة. التأكيد مرتبط بـ`summary_version` و`confirmed_digest`; احفظه كمسودة تمت مراجعتها فقط.

جسم التأكيد والاستئناف:

```json
{"expected_revision": 7}
```

جسم حل التعارض الزمني:

```json
{
  "expected_revision": 8,
  "field": "initial_time",
  "selected_value": "مبارح حوالي الساعة 6 المسا",
  "resolution_reason": "هذه إفادة البداية الصحيحة"
}
```

`field` يقتصر على `initial_time`, `latest_time`, `discovery_time`, أو `account_creation_time`. يجب أن يطابق `selected_value` أحد البدائل المسجلة حرفيًا، وسبب القرار مطلوب. يحتفظ سجل الحقيقة بتاريخ الحالة المتعارضة وبدائلها، ثم يسجل الاختيار والسبب. لا تنفذ قراءة الحالة أو التقرير هذا الحل، ولا يُؤكد الملخص تلقائيًا بعده.

## الإصدارات والأخطاء

يحتوي كل `session` على `revision`. خزّن الرقم الذي عاد من أحدث عملية ناجحة، وأرسله في كل تعديل. إذا عدّل طرف آخر الجلسة، يعيد API الحالة `409` مع `current_revision`؛ أعد القراءة واعرض التغييرات للمستخدم قبل إعادة المحاولة، ولا تعاود إرسال الرسالة آليًا. رموز مهمة أخرى: `403` رمز جلسة غير صحيح، `404` جلسة غير موجودة، و`422` إدخال أو قرار غير صالح. قد تُرجع الأعطال غير المتوقعة `500` برسالة عامة.

لا تستنتج أن `revision` أو `summary_version` رقم بلاغ ACCP؛ احتفظ بكل منهما في حقل منفصل. ويجب استخدام صلاحيات ACCP الخاصة بالمستخدم والبلاغ عند كل طلب، لا الاعتماد على معرف Python وحده.

## حقول التقرير

يرجع `report.json` كائن التقرير الحالي ويشمل على الأقل، بحسب النسخة والحقول الموجودة:

- `session_id`, `revision`, `stage`, `summary_version`, `confirmed`, `confirmed_digest` وسجل التأكيد.
- `facts`: خريطة اسم الحقل إلى `status`, `value`, `quote`, `message_id`, `question_id`, `source`, `updated_at`, و`history` أو `supporting_statements` أو بدائل التعارض عند وجودها.
- `messages`: الرسائل الأصلية وردود المساعد والأسئلة والتوضيحات؛ الاقتباسات تُحفظ كما وردت ولا يعاد تحريرها بصمت.
- `money_events` و`money_corrections`: دفتر أحداث ومراجعات مالية append-only؛ سجلات التصحيح ليست دفعات جديدة.
- `assessment`, `unresolved_fields`, والمصادر/الاستشهادات حين تنطبق.

تعامل مع `status` مستقلاً عن `value`: مثل `unknown`, `not_remembered`, `declined`, `denied`, `reported`, `conflict`, و`unresolved`. لا تحول غياب القيمة إلى نفي. درجات الفرز تجريبية وليست احتمالات إحصائية أو قرارًا قانونيًا. يلزم عرض الاقتباس والمصدر والحالة معًا للمراجع.

احفظ التقرير في ACCP بوصفه **مسودة مرتبطة بإصدار**، مع رابط إلى `PythonSessionId` و`summary_version` و`confirmed_digest` ووقت الاستيراد. افحص الصلاحيات والتأكيد قبل النسخ، وسجّل أن التأكيد هو من المستخدم وأن الملف ليس بلاغًا مقدمًا. لا تستبدل تقريرًا محفوظًا على نحو غير قابل للاسترجاع؛ احتفظ بسجل نسخ وفق سياسة ACCP.

## فحوص الربط المطلوبة في مشروع C# قبل الإنتاج

لم يُراجع مستودع C# بعد. قبل تنفيذ الربط، تحقّق من نموذج حساب ACCP والبلاغ، وسياسة التخزين/الحذف/الاحتفاظ، ومكان حفظ السر، وآلية صلاحيات المستخدمين، وحدود الشبكة بين .NET وPython، والتعامل مع `409` وعمليات إعادة المحاولة، وترميز النص العربي، ومزامنة النسخ والتأكيد، وسجل التدقيق. اختبر الربط في بيئة اصطناعية أولًا؛ لا تستخدم بيانات واقعية أو تعلن جاهزية تشغيلية بناء على اختبارات Python وحدها.
