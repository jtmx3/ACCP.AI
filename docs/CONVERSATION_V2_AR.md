# ACCP.AI — تطوير فهم المحادثة v2

هذا الدليل يصف فرع `feature/accp-conversation-v2` المبني على تحديث التوثيق `4466c51ebcc2ea51c67291a47f22e263ccbdcfdb`. لا يغيّر PR #1 أو مرجع البرنامج `25ae703`.

## تدفق الرسالة

1. يفحص API إصدار الحالة `expected_revision` قبل أي اتصال اختياري، ثم يمرر الرسالة على فحص السلامة المحلي. الإفصاح عن خطر مباشر لا ينتظر النموذج أو الاسترجاع.
2. يحلل `app/conversation.py` أهداف الرسالة كإشارات **غير متنافية**، مثل إجابة السؤال، إضافة أو تصحيح واقعة، تأكيد مرجع سابق، سؤال «لماذا؟»، سؤال إرشادي، جهل/تذكر/امتناع. تفسير الهدف لا يعدّل الحالة بذاته، وتظل اقتراحاته غير موثوقة.
3. يحفظ المحرك المحلي الرسالة والاقتباس والمصدر، ويفصل المجالات: جهل هوية الفاعل لا يمحو توفر الأدلة أو وسيلة التواصل، ووقت الاكتشاف لا يثبت وقت إنشاء الحساب، والدفع لا يجيب عن المهلة ولا ينشئ مبلغًا مفقودًا. التصحيح يستهدف الحقل أو الحدث المدعوم ويحفظ التاريخ السابق.
4. إذا وافق المستخدم على استخراج اختياري، يمكن إرسال الرسالة الحالية إلى المزود المختار. **السياق السابق له موافقة منفصلة**: مربع اختياري مستقل في الواجهة، غير محدد افتراضيًا، ولا يكفي تفعيل موافقة الرسالة الحالية لإرساله. حد السياق 4500 حرف، ويشمل حتى أربع عناصر رسائل حديثة (بما فيها السؤال المعلّق)، حتى 10 حقائق وأربعة أحداث مالية ذات صلة مع حالاتها ومراجعها. لا يشمل سجل الحالة كاملًا أو معرّفها أو رمزها؛ ويُعامل كل السياق وتلميحات الأهداف كبيانات غير موثوقة.
5. يظل اقتباس النموذج مثبتًا إلى نص الرسالة الحالية ويمر عبر مخطط وتحقق محليين. يحجب الدمج حقول السلامة/القرار، ويوجه مبالغ الأحداث عبر محلل العلاقات، ويصون أولوية الوقائع المحلية عند الاختلاف. يسجل API `model_merge_trace` حقولًا وحالات دمج دون نصوص الرسائل.
6. يختار التطبيق سؤال متابعة واحدًا محليًا، مع خطة تعرض الحقل والسبب وشرط الحاجة. الرسالة التي تجمع معلومة وسؤالًا إرشاديًا تحفظ المعلومة، وتضيف جوابًا مستندًا إلى RAG المحلي عند وجود مصدر، ثم تستأنف السؤال المعلّق؛ لا يُسجّل الجواب الإرشادي كواقعة.
7. تستمر كتابة SQLite والتحقق من الإصدار والذرية كما في المسار الحالي. أي تعديل جوهري يبطل تأكيد النسخة التي تغيرت.

## مجموعة التقييم والمقاييس

المجموعات في `tests/conversation_v2_acceptance.json` و`tests/conversation_v2_development.json` و`tests/conversation_v2_holdout.json` **اصطناعية داخلية**. المجموعة الأساسية ثُبتت قبل تعديل المنطق، ومجموعة الصيغ البديلة منفصلة؛ ومجموعة holdout ليست مراجعة بشرية أو عينة مستخدمين. نتائج القواعد لا تقيس النموذج.

| المقياس | التعريف والمقام |
|---|---|
| نجاح السيناريو المتكامل | عدد السيناريوهات التي نجحت كل فحوص جميع أدوارها ÷ عدد السيناريوهات. يشمل استخدام القواعد المحلية، ولا يسمى نجاح النموذج. |
| مطابقة الوقائع | فحوص الحقول والحالات والقيم المعلنة في التوقعات ÷ مجموع فحوص الوقائع. |
| منع الإضافة غير المسندة | فحوص الحقول المحظورة صراحةً، ومبالغ غير مخترعة، التي لم تظهر ÷ مجموع تلك الفحوص. لا يُعد الحقل غير المدرج نفيًا إلا إذا كان محظورًا صراحةً. |
| فحوص الحوار | فحوص المرحلة والسؤال المعلّق وعدد أسئلة المتابعة وعلاقات التصحيح/الإحالة ÷ مجموع الفحوص المعلنة. |
| مطابقة استخراج النموذج وحده | في وضع `model` فقط: الحقائق المتوقعة المؤهلة التي يخرجها النموذج وتطابق الحالة/القيمة ÷ فحوص الحقائق المؤهلة التي لم تكن محسومة مسبقًا في الحالة الابتدائية. لا تدخل نتائج fallback. |
| الحذف/الإضافة المحظورة للنموذج | المحذوفات = فحوص النموذج المؤهلة ناقص المطابقات؛ والإضافات المحظورة تُحسب فقط ضد `absent` و`no_invented_amounts` الصريحة. |
| قبول بنية النموذج | محاولات الاستخراج ذات الاستجابة/المخطط الصالح تسجل منفصلة عن `extracted` و`valid_empty` و`all_facts_filtered` و`response_rejected` و`provider_failed`. البنية الصالحة الفارغة ليست نجاح استخراج. |
| دمج اقتراحات النموذج | يحصي المقترحات المطبقة، المطبقة كتصادم، الموافقة لقواعد سابقة، الموجهة لمحلل العلاقات، المتجاهلة، والمستبدلة بقواعد محلية؛ لا يخلطها مع مقياس الاستخراج المنفصل. |
| الزمن والرجوع | زمن المزود منفصل عن زمن طلب API، مع تسجيل أول محاولة والطلبات اللاحقة. عدد الرجوع إلى القواعد منفصل ولا يحتسب نجاحًا للنموذج. |

بقيت في مجموعة holdout ثلاث حالات غير ناجحة: مرجع «العثور على الحساب» مقابل وقت الإنشاء، صيغة بديلة لادعاء الهوية، واستقلال جهل هوية الفاعل عن دليل محفوظ. لم تُعدّل توقعات المجموعات القديمة لتوافق السلوك، ولم تُستخدم هذه الحالات لتغيير الشيفرة بعد التشغيل النهائي. كل هذه الأرقام قواعد محلية على حالات اصطناعية، وليست precision/recall لمستخدمين أو مراجعة مستقلة.

التقييم القديم `tests/evaluation_scenarios.json` ظل بلا تغيير وأُعيد على القواعد: **21/21** حالة متكاملة، **0** استدعاءات مزود. هذا لا يثبت نجاح استخراج النموذج.

لم يُشغّل نموذج حي في هذه البيئة: إعداد التطبيق هو `MODEL_PROVIDER=rules`، `configuration_complete=false`، ولا يوجد إعداد Ollama محلي متاح. لذلك لم يصدر أي طلب استخلاص للمزود. سجلت النسخة المحدثة من الأداة هذه النتيجة على أنها `status: not_run` و`results: []` في `reports/evaluation/conversation-v2-model-not-run-final-2026-11-04.json`، وبحالة خروج 2. لم أستخدم مفتاح OpenAI المتاح للبيئة بدل Ollama، ولم أختلق نتيجة نموذج. اختبار evaluator الوهمي يختبر فصل المقاييس والدمج فقط؛ لا يثبت اتصالًا أو جودة نموذج حقيقي.

## Windows — الاختبارات والتقييم المحلي

الأوامر التالية تفترض أن `.venv` الموجودة في مجلد المشروع مبنية مسبقًا؛ لا حاجة لإعادة إنشائها. لتشغيل اختبارات المستودع:

```powershell
Set-Location C:\path\to\accp-ai
.\.venv\Scripts\python.exe -W error::ResourceWarning -m unittest discover -s tests -v
```

لتقييم القواعد المحلية على المجموعات الثلاث (لا يتصل بمزود):

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_conversation_v2 `
  --mode rules --suite both `
  --output reports/evaluation/conversation-v2-rules-windows.json
```

لتقييم Ollama فعليًا بعد تشغيله ووجود النموذج المذكور في `ollama list`:

```powershell
$env:MODEL_PROVIDER = "ollama"
$env:MODEL_BASE_URL = "http://127.0.0.1:11434/v1"
$env:MODEL_NAME = "qwen3.5:4b-q4_K_M"
$env:OLLAMA_REASONING_EFFORT = "none"
$env:MODEL_TIMEOUT_SECONDS = "120"
.\.venv\Scripts\python.exe -m scripts.evaluate_conversation_v2 `
  --mode model --suite both --preflight-timeout 5 `
  --output reports/evaluation/conversation-v2-model-windows.json
```

هذا الوضع يجري preflight، ثم يستدعي النموذج مرة لكل دور مؤهل في المجموعات الاصطناعية. `--preflight-timeout` يحدد مهلة فحص الخدمة/قائمة النموذج فقط؛ مهلة كل استخراج يحددها `MODEL_TIMEOUT_SECONDS`. افتراضيًا يرسل رسالة الدور الحالية فقط. لإضافة السياق الاصطناعي المحدود عمدًا، أضف الخيار المستقل `--include-bounded-context`؛ لا يتجاوز ذلك حد السياق المذكور ولا يرسل جلسات حقيقية. استخدم ملف إخراج جديدًا لكل تشغيل ولا تنسب `valid_empty` أو fallback إلى نجاح استخراج.

تجربة نموذج فعلي واختبارات Windows على فرع v2 لم تُنفّذ في بيئة التطوير هذه. الحالة النموذجية الوحيدة الحية السابقة تخص ما أبلغ به صاحب المشروع على مرجع `25ae703`؛ لا تُنسب إلى هذا الفرع أو إلى تشغيل حالي.

## الملفات التي تغيّرت

- `app/conversation.py`: تفسير أهداف متعددة وبناء السياق المحدود.
- `app/core.py`: التعامل المرحلي مع المرجع/الجهل/التصحيح وحالة الحقول، وخطط السؤال.
- `app/main.py`: موافقة السياق المنفصلة، مرور الرسائل المختلطة، تشخيص قرار الدمج.
- `app/model.py`: اعتبار تلميحات الأهداف والسياق بيانات غير موثوقة.
- `static/index.html`, `static/app.js`, `static/style.css`: شرح نطاق الإرسال ومربع الموافقة المنفصل للسياق، وعرض خطة السؤال.
- `scripts/evaluate_conversation_v2.py`: تشغيل القواعد أو النموذج، بفصل المقاييس وحساب fallback/الدمج والزمن.
- `tests/conversation_v2_*.json`: مجموعات القبول والتطوير والصيغ الاصطناعية.
- `tests/test_conversation_v2.py`, `test_evaluate_conversation_v2.py`, وتعديلات اختبارات API والنموذج والمتصفح وسير العمل: اختبارات مرحلية ووهمية ومحلية.
- `reports/evaluation/conversation-v2-baseline-2026-11-04.json`, `conversation-v2-rules-final-recheck-2026-11-04.json`, `conversation-v2-model-not-run-final-2026-11-04.json`, و`rules-original-oracle-conversation-v2-2026-11-04.json`: baseline، القواعد النهائية، فشل preflight الصريح، وإعادة oracle القديم.

## القيود المتبقية

التفسير محلي/قائم على قواعد ومحدود باللهجات والمرادفات؛ لا يضمن فهم كل رسالة أو كل علاقة. الحالات اصطناعية داخلية، وholdout يتضمن إخفاقات، ولا يوجد نموذج حي مجرب في هذا التنفيذ. لا يوجد تقييم بشري مستقل أو مجموعة مستخدمين ممثلة أو مراجعة سلامة/قانونية أو اختبار أمان/ضغط أو إعداد إنتاجي. المشروع أداة عرض وتجريب ببيانات اصطناعية، وليس خدمة بلاغ أو إخطار جهة.
