# دليل التسليم — ACCP.AI

**الغرض:** نموذج أولي يعمل محليًا لتسجيل إفادة عربية عن واقعة رقمية، وطرح أسئلة تكيفية، وحفظ مصدر كل حقل، وعرض فرز تجريبي وملخص للمراجعة. بُني المشروع في مستودع كان فارغًا عند بدء التنفيذ؛ لا توجد خدمة إنتاج أو واجهة قائمة جرى ربطها.

## معمارية المكوّنات

- `static/index.html`, `static/style.css`, `static/app.js`: واجهة RTL عربية. تحتفظ بسياق مستقل لكل طلب (معرّف الجلسة، الرمز، الإصدار والجيل النشط)، وتمنع رد جلسة قديمة من استبدال جلسة نشطة أخرى. يوجد قفل عمليات كتابة لكل جلسة، وتبقى المسودات عند الخطأ الملتبس. تستخدم الواجهة `textContent` لعرض كلام المستخدم.
- `app/main.py`: FastAPI، إنشاء/قراءة الجلسات، الرسائل، السؤال المحلي، تغيير الاختصاص، الاستكمال، التأكيد، التقرير وسجل التدقيق. يتحقق أولًا من هوية الجلسة ورقم الإصدار. تنتهي استدعاءات المزود الاختيارية قبل بدء معاملة كتابة SQLite، ثم تُرفض النتيجة إذا تغير الإصدار أثناء انتظارها.
- `app/core.py`: نموذج الوقائع، قواعد استخراج محلية، الاقتباسات ومصدرها، اختيار السؤال التالي، سياسة الفرز، مراجعة المستخدم، والتقرير. يفصل مثلًا التهديد عن حدوث النشر، والمال المطلوب عن المدفوع، والانتحال عن اختراق حساب المستخدم. كاشف الخطر المباشر عالي الثقة يتجاوز التحكم العادي والسؤال/RAG، لكن تغطيته اللغوية محدودة.
- `app/store.py`: SQLite محلي ورمز bearer عشوائي مستقل لكل جلسة، كتابة ذرية والتحقق من `expected_revision`.
- `app/rag.py` و`data/knowledge.json`: بحث lexical محدود حسب الاختصاص، مع مقتطف فعلي من المصدر وبياناته. خيارات الاختصاص مشتقة من سجلات المصادر. عند ضعف التطابق أو غياب البلد يمتنع النظام عن تقديم استنتاج محلي. الأمر `--reindex` يتحقق من ملف JSON وبيانات المصدر فقط؛ لا ينشئ embeddings أو فهرسًا دلاليًا.
- `app/model.py`: موائم اختياري لـOllama المحلي أو لمزود OpenAI-compatible. يفصل حالة الإعداد عن اتصال الخدمة ووجود النموذج ونجاح توليد JSON. يحدّث جواب الإرشاد من مقتطفات المصدر الحرفية فقط، أو يقترح حقائق منظمة مع اقتباس حرفي من الرسالة الحالية. تمنع حواجز الدمج اقتراحات المبالغ من تجاوز محلل علاقة الدفع، وترفض قناة عامة مثل «رسالة خاصة» كمعرّف، وتتحقق من السياق المؤذي قبل تكرار التهديد، وتحفظ السرد الأول وتمنع دفعة وحدها من إكمال تفاصيل الواقعة.
- `tests/`: اختبارات قواعد، SQLite/API، مزود وهمي، تزامن HTTP/browser، وتدفق Chromium end-to-end. لا تحتاج الاختبارات إلى مفتاح نموذج حقيقي.

## رحلة البيانات والخصوصية

1. ينشئ المتصفح جلسة عبر `POST /api/sessions` ويحفظ رمزها في `localStorage`. لا يكفي معرف الجلسة للوصول؛ يلزم `X-Case-Token`.
2. تُراجع صلاحية الرمز و`expected_revision` قبل استدعاء اختياري للمزود. يُرسل طلب المزود خارج قفل الكتابة. إذا تغيّرت الحالة خلال الانتظار، ترفض الكتابة القديمة بـ `409` ولا تُعاد تلقائيًا.
3. كل حقل محلي يحتفظ بحالة مثل `reported`, `denied`, `unknown`, `not_remembered`, `declined`, `unresolved`, `conflict` وبالاقتباس الحرفي ومرجع الرسالة/السؤال. لا تُعامل عبارة «صور خاصة» في سياق تهديد وحدها كدليل يمتلكه المستخدم؛ ولا يُعامل ذكر حساب كمُعرّف تواصل محدد دون رقم/اسم مستخدم واضح.
4. فحص الخطر المباشر يسبق إيقاف المقابلة، وشرح السؤال، والأسئلة/الإجابات العادية. في وضع السؤال يتجاوز التصريح الشخصي عالي الثقة عن خطر حالي RAG والمزود. يبقى الكاشف قواعد محدودة وليس فهمًا لغويًا شاملًا.
5. السؤال الواضح المكتوب أثناء المقابلة يُكتشف دون تبديل الوضع؛ يجيب النظام محليًا، ثم يعيد سؤال المقابلة المعلّق. وضع السؤال اليدوي، بعد موافقة منفصلة، يرسل نص السؤال الحالي ومقتطفات المصدر التي استرجعها النظام. وضع المقابلة، بعد موافقة مستقلة، يرسل نص الرسالة الحالية فقط مع خانة السؤال المعلّقة لتقييد استخراج حقائق منظمة. لا يُرسل سجل المحادثة، أو الرموز، أو الإجابات السابقة تلقائيًا. أي بيانات شخصية داخل الرسالة الحالية ستكون ضمن الطلب الذي وافق عليه المستخدم.
6. يعيد النظام مقتطفات المصدر نفسه. لا ينتج نصًا حرًا من المزود إلا إذا احتوى الرد على اقتباسات صالحة من المقتطفات المقدمة. خطأ المزود أو رفض المخرجات يرجع إلى قواعد محلية/جواب RAG.
7. التأكيد مربوط بإصدار الملخص الحالي. التغييرات تبطل التأكيد؛ والتعارض غير المحسوم يمنع التأكيد. تنزيل JSON وMarkdown والطباعة تحدّث الحالة أولًا لتطابق النسخة المعروضة وحالة تأكيدها. يفصل الملخص بين حالة الحقل وقيمته ووقت الرسالة الأصلية وآخر تحديث. التقرير لا يثبت الواقعة ولا يرسل بلاغًا رسميًا.

## ترحيل البيانات الموجودة

لم يتغير مخطط SQLite (`sessions` و`audit_log`) ولا شكل حفظ JSON داخل الجلسة في هذا التحديث؛ لا يلزم ترحيل مخطط. يحتفظ `ACCP_DB_PATH` الحالي بالجلسات كما هي، وتُقرأ الوقائع القديمة عبر القواعد الحالية، بينما تظهر الحقول الجديدة عند استخراجها من رسائل لاحقة. خذ نسخة احتياطية اعتيادية لملف قاعدة البيانات قبل أي تحديث تشغيلي، ولا تحذف الملف أو تنشئ قاعدة جديدة فوقه.

## قيود الأمن والخصوصية

- التشغيل المحلي افتراضيًا، لكن SQLite غير مشفر. رمز الجلسة مخزن في `localStorage` ويمكن أن يقرأه مستخدم الجهاز أو سكربت خبيث. استخدم بيانات اصطناعية، وتجنب الأجهزة المشتركة.
- لا يوجد تسجيل دخول أو ملكية متعددة المستخدمين أو حماية نشر عام أو تشفير قاعدة البيانات أو سياسة حذف من الواجهة. يلزم قبل بيانات حقيقية: مصادقة، TLS، تشفير ومفاتيح، صلاحيات، احتفاظ/حذف، تدقيق، حدود طلبات، معالجة XSS/CSRF/CORS، ومراجعة تهديدات.
- التطبيق لا يرفع ملفات أو يفحص أدلة، ولا يتصل بجهة حكومية، ولا يثبت تقديم شكوى. مصدر رقم طوارئ أردني لا يحول النموذج إلى خدمة طوارئ.
- لا تضبط `0.0.0.0` ولا تنشر قاعدة البيانات. لا تضع `MODEL_API_KEY` في Git أو الواجهة أو ملف مشترك. حتى نجاح اختبار التوليد والتقييم الاصطناعي لا يثبت ملاءمة النموذج للاستخدام الإنتاجي أو صحة الفرز.

## التشغيل

Python 3.10 أو أحدث. على Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
set -a; . ./.env; set +a
python -m app.rag --reindex
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

على Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m app.rag --reindex
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

افتح <http://127.0.0.1:8000>. لا يحتاج التشغيل المحلي إلى `.env` أو مفتاح نموذج. قاعدة البيانات الافتراضية `data/accp.sqlite3`.

### تشغيل نموذج Ollama محلي على Windows

ثبّت Ollama من دليل Windows الرسمي وشغّله. في إعادة اختبار F83 استخدم وسم الجهاز الذي أبلغ عنه المشغّل `qwen3.5:4b-q4_K_M` كما يظهر في `ollama list`؛ لا تستبدله بوسم آخر. راجع [`PROVIDER_SETUP_AR.md`](PROVIDER_SETUP_AR.md) لفحص الاتصال والتشخيص بالموجه الحقيقي.

```powershell
ollama --version
ollama pull qwen3.5:4b-q4_K_M
ollama list
Set-Location C:\path\to\accp-ai
.\.venv\Scripts\Activate.ps1
$env:MODEL_PROVIDER = "ollama"
$env:MODEL_BASE_URL = "http://127.0.0.1:11434/v1"
$env:MODEL_NAME = "qwen3.5:4b-q4_K_M"
$env:MODEL_TIMEOUT_SECONDS = "120"
$env:OLLAMA_REASONING_EFFORT = "none"
python -m app.rag --reindex
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

بعد فتح الواجهة، اضغط **فحص الإعداد والخدمة والنموذج** ثم **اختبار توليد ثابت**. يفحص الأول قائمة النماذج دون إرسال نص حالة؛ ولا يتاح الثاني حتى تظهر الخدمة والاسم كمتاحين. يستخدم التوليد التشخيصي نصًا ثابتًا. لا يكفي ضبط المتغيرات لإثبات الاتصال.

## الاختبارات وCI

لتشغيل كل الاختبارات بما فيها المتصفح:

```bash
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
python -m unittest discover -s tests -v
node --check static/app.js
python -m app.rag --reindex
```

في Ubuntu يمكن استخدام `python -m playwright install --with-deps chromium`. سير العمل `.github/workflows/tests.yml` يشغل فحوص Python/JavaScript، تحقق corpus، اختبارات القواعد وAPI والتزامن، وChromium end-to-end عند الدفع وفتح PR.

الاختبارات تشمل: السيناريو العربي المرجعي، النفي والتكرار، خطر مباشر في مواضع متعددة، دليل منفي، الحساب المنتحل، الفصل بين المال المطلوب والمدفوع، الاقتباسات والمبالغ، حدود الاسترجاع الجغرافي، التحقق من رموز الجلسة والإصدارات، timeout/المخرجات غير المقبولة للمزود، انتظار المزود خارج قفل SQLite، رفض نتيجة قديمة دون إعادة الإرسال، تدفق المتصفح من المقابلة إلى التعديل والتأكيد والتنزيل، ورد جلسة A المتأخر بينما B نشطة حتى مع تساوي رقم الإصدار.

## نتائج التقييم الأخير — 2026-11-04

- نجح آخر تشغيل لـ`python -W error::ResourceWarning -m unittest discover -s tests -v` في **103/103** اختبارًا، ونجحت فحوص Python وJavaScript و`git diff --check`. يشمل اختبارات الإغلاق الصريح لاتصالات SQLite عند النجاح والاستثناء، وrollback، وإمكان إزالة قاعدة مؤقتة، وتسلسل F83 واختبار Chromium للموافقة.
- كان `with self._connect() as conn` لا يغلق الاتصال تلقائيًا؛ يستخدم المخزن الآن سياق `_connection()` يغلقه في `finally` ويتراجع عن المعاملات النشطة عند الاستثناء، بينما يغلق `_connect()` المقبض إذا فشل PRAGMA قبل تسليمه. بقي WAL و`BEGIN IMMEDIATE` والتحقق من `expected_revision` كما هي.
- اختبار API والمخزن نجح **25/25**، واختبار موافقة المتصفح المحدد نجح **5 مرات متتالية**. تم تقييم القواعد **21/21** دون تغيير التوقعات أو استدعاء نموذج. هذه النتائج من Linux/Python 3.12؛ لا تتوفر Windows/Python 3.14 في بيئة التنفيذ، لذا يجب إعادة التشغيل هناك للتحقق المباشر من `WinError 32`.
- اجتاز تقييم القواعد المحلية الثابت **21/21** بصفر إخفاقات وصفر استدعاءات نموذج. الملف: [`rules-v5-final-2026-11-04.json`](../reports/evaluation/rules-v5-final-2026-11-04.json).
- فُحص مزود OpenAI-compatible فعلي (`gpt-6-luna`)، وأثبت التشغيل الحي توافر الخدمة والنموذج ونجاح توليد JSON. في تقييم v5 الاصطناعي، اجتاز النموذج **18/21 حالة استخراج** وطابق **43/46** حقيقة مؤهلة؛ كانت 76/76 استجابة JSON ومخططًا صالحين، مع 5 اقتراحات حقائق مفلترة على مستوى الحقل. واجتاز المسار المتكامل 21/21 باستخدام محرك القواعد أيضًا. لا تُفسَّر نتيجة النظام المتكامل على أنها دقة للنموذج.
- صُحح تعريف الاستخراج ليستثني `direct_danger` وحقول القرار التي يديرها المحرك، ويُحتفظ بالتوقعات القديمة للمسار المتكامل. صُحح أيضًا رفض الاستجابة كلها عند تعارض حقل واحد؛ يعرض [تقرير تشخيص v5](../reports/evaluation/تقرير_تشخيص_تقييم_النموذج_v5_2026-11-04.md) المقامات، والرفض/التصفية، وإعادة الحساب غير المتصلة على مخرجات v4 نفسها، والقيود.
- نتيجة **5/21** التاريخية تخص المقياس المركب v2، الذي احتوى حقلًا غير مسموح للنموذج ولم يحفظ تفاصيل 16 رفضًا. لم تُلغَ هذه النتيجة؛ لكنها ليست «دقة للنموذج وحده» وغير قابلة للمقارنة المباشرة بمقياس التغطية v5. ملفها التاريخي: [`model-live-gpt-6-luna-final-narrative-guard-2026-11-03.json`](../reports/evaluation/model-live-gpt-6-luna-final-narrative-guard-2026-11-03.json).
- جميع الحالات اصطناعية وليست مراجعة بشرية. فحص مزود `gpt-6-luna` الحي السابق جرى من Sandbox الخارجي. إصلاح Ollama الحالي اختُبر بموائم HTTP وهمي فقط: `ollama` CLI غير مثبت وواجهة `127.0.0.1:11434` غير متاحة في بيئة التنفيذ، لذا لا ندّعي تشغيل Ollama حقيقيًا أو تجربة Windows. أمر PowerShell واحد يستخدم برومبت المشروع الحقيقي ويعرض الزمن والحقائق المقبولة وأسباب التصفية موثق في [`PROVIDER_SETUP_AR.md`](PROVIDER_SETUP_AR.md)، ولم يُنفذ على جهاز المستخدم.
- في إعادة حالة F83، سبب التعارض الزائف قاعدة تطبيع وسيلة الدفع التي لم تتعرف على صيغة «المحفظة الإلكترونية» فتحفظ نص الرسالة كله؛ لم يكن نجاح fallback أو تعديل النموذج. سبب أوقات Markdown المفقودة استخدام renderer للوقائع الخام بدل إسقاط JSON المشتق من timestamps الرسائل. ملخص الأسباب والاختبارات المحددة في [`VALIDATION_AR.md`](VALIDATION_AR.md).

## قيود التقييم والعمل اللاحق

- تغطية النفي والعامية محدودة بقواعد وعينة اصطناعية؛ لا توجد Precision/Recall مستقلة، معايرة، تقييم سلامة ممثل، أو تدقيق مختصين.
- لا توجد مراجعة بشرية مستقلة لنتائج النموذج أو اختبار اختراق أو ضغط/تحميل أو نشر متعدد المستخدمين. تقييم النموذج الفعلي يستعمل الرسائل الاصطناعية الثابتة فقط، ولا يمثل اختبارًا على مستخدمين أو اعتمادًا إنتاجيًا. اختبارات التزامن محاكاة داخلية وHTTP محلي وليست ضمان إنتاج.
- الصلة المعجمية لا تفهم المعنى كاملًا؛ يلزم توسيع مجموعة اختبارات الاسترجاع والسياق والنفي والمختصرات واللهجات لكل مصدر جديد.
- يلزم قبل الاستخدام مع إفادات حقيقية: مراجعة مختصين مستقلين للسلامة والخصوصية والسياسة، تقييم مجموعة ممثلة، اختبار أمان ونشر مصادق، وحوكمة واضحة للاحتفاظ والحذف.
