# إعداد موفر النموذج المحلي أو المتوافق

**ملاحظة المصادر:** تمت مراجعة توثيق Ollama الرسمي في 2026-11-03. هذه الصفحة تصف واجهات الاتصال كما يوثقها المزود، ولا تعني أن النموذج مناسب لفرز أمني أو قانوني.

يوثق Ollama واجهة متوافقة جزئيًا مع OpenAI على `http://localhost:11434/v1`، بما فيها `POST /v1/chat/completions` ووضع JSON. وثائقهم تبين أن عميل OpenAI يمرر قيمة لمفتاح API محليًا، لكن خادم Ollama المحلي يتجاهلها؛ أما الوصول المباشر إلى خدمة Ollama السحابية فيحتاج مفتاحًا حقيقيًا. لذلك يجب التفريق بين موفر محلي وموفر متوافق بعيد وعدم عرض «متصل» لمجرد ضبط الإعدادات. [1] [2] [3]

تعرض واجهة `/v1/models` قائمة النماذج المتاحة في توافق OpenAI. كما يوثق Ollama واجهة محلية مستقلة `GET /api/tags` لسرد النماذج. يمكن إجراء فحص اتصال غير توليدي باستعلام قائمة النماذج، ثم مقارنة اسم النموذج المضبوط بالقائمة، من دون إرسال رسالة مستخدم أو تشغيل استدلال. [1] [4]

لا يُرسل التطبيق أي نص إلى موفر لاختبار الاتصال. أما توليد إجابة أو استخراج اختياري فيبقى مرتبطًا بموافقة منفصلة لكل طلب، ويجب أن يعرض النظام بوضوح هل جرت محاولة الإرسال، وهل قُبلت نتيجة سليمة، أو حصل رفض/مهلة/تعذر اتصال فعاد النظام إلى القواعد المحلية.
