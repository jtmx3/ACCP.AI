# إعداد النموذج المحلي أو المزود المتوافق

**الافتراضي آمن ومحلي:** عند `MODEL_PROVIDER=rules` يعمل ACCP.AI بالقواعد المحلية، ولا يرسل رسائل إلى نموذج. إعداد المزود لا يثبت أن الخدمة متاحة أو أن النموذج موجود أو أن التوليد ينجح. تعرض الواجهة هذه المراحل منفصلة، ويمكن فحص القائمة دون إرسال بيانات الحالة، ثم إجراء اختبار توليد بنص ثابت.

يدعم Ollama على Windows تطبيقًا أصليًا يعمل كخدمة خلفية محلية. توثيق Ollama يذكر عنوان API المحلي `http://localhost:11434` وواجهة متوافقة جزئيًا مع OpenAI على `http://localhost:11434/v1`، ومنها `/v1/chat/completions` و`/v1/models` ووضع JSON. كما يتيح `GET /api/tags` تعداد النماذج المحلية. [1] [2] [3]

## Windows PowerShell — Ollama محلي

1. ثبّت Ollama من دليل Windows الرسمي، ثم شغّله واتركه يعمل في الخلفية. يتطلب Windows 10 22H2 أو أحدث بحسب دليل المزود. في تجربة Windows التي أبلغ عنها المستخدم، اسم النموذج المضبوط هو `qwen3.5:4b-q4_K_M`؛ أبقِ الاسم كما يظهر في `ollama list` ولا تستبدله عند فحص هذا الإصلاح. [1]

```powershell
ollama --version
ollama pull qwen3.5:4b-q4_K_M
ollama list
```

2. في PowerShell نفسه الذي ستشغّل منه التطبيق، اضبط المزود المحلي واسم النموذج كما يظهر حرفيًا في `ollama list`:

```powershell
Set-Location C:\path\to\accp-ai
.\.venv\Scripts\Activate.ps1
$env:MODEL_PROVIDER = "ollama"
$env:MODEL_BASE_URL = "http://127.0.0.1:11434/v1"
$env:MODEL_NAME = "qwen3.5:4b-q4_K_M"
$env:MODEL_TIMEOUT_SECONDS = "120"
$env:OLLAMA_REASONING_EFFORT = "none"
python -m app.rag --reindex
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

لا يلزم `MODEL_API_KEY` لموائم Ollama المحلي؛ يرسل الموائم قيمة محلية شكلية لأن العميل المتوافق يتوقع ترويسة، ويتجاهلها خادم Ollama المحلي. لا تستخدم هذا الافتراض مع خدمة Ollama سحابية أو مزود بعيد. [2]

`OLLAMA_REASONING_EFFORT` إعداد محلي مستقل يُرسل إلى واجهة Ollama المتوافقة كالحقل `reasoning_effort`، وقيمه المقبولة `none` و`low` و`medium` و`high`. الافتراضي `none` لتعطيل التفكير الممتد في طلبات Ollama، ومنها استخراج الوقائع. لا يقرأ هذا الخيار إعداد المزود الخارجي `MODEL_REASONING_EFFORT` ولا يغيّره؛ يظل الأخير مستقلًا للمزود `openai-compatible`. تعرض لوحة التشغيل إعداد Ollama الفعلي. لا يغيّر هذا الخيار مهلة HTTP؛ ارفع `MODEL_TIMEOUT_SECONDS` إذا احتاج النموذج وقت تحميل، مع العلم أن طول المهلة لا يضمن صحة الاستخراج.

3. افتح `http://127.0.0.1:8000`، ثم استخدم لوحة **مسار التشغيل الفعلي**. زر الفحص يختبر الإعداد واتصال قائمة النماذج وتطابق الاسم؛ لا يرسل رسالة حالة ولا يشغّل توليدًا. بعد نجاحه، زر اختبار التوليد يرسل نص JSON ثابتًا لا يتضمن بيانات المستخدم.

يمكن أيضًا فحص المراحل من PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health | ConvertTo-Json -Depth 5
Invoke-RestMethod http://127.0.0.1:8000/api/provider/status | ConvertTo-Json -Depth 5
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/provider/test `
  -ContentType "application/json" -Body "{}" | ConvertTo-Json -Depth 5
Test-NetConnection 127.0.0.1 -Port 11434
```

`/api/health` يعرض الإعداد المختار فقط. `/api/provider/status` يجري فحصًا غير توليدي للخدمة وقائمة النماذج. `/api/provider/test` لا يجري التوليد إلا بعد توافر الإعداد والخدمة والنموذج. النتيجة الناجحة تعني أن اختبار JSON الثابت نجح، ولا تثبت جودة الاستخراج العربي أو السلامة أو صلاحية المنتج.

### أمر تشخيص استخراج واحد على Windows

من جذر المستودع، وبعد تفعيل البيئة الافتراضية وتشغيل Ollama محليًا، انسخ السطر التالي إلى PowerShell. يستخدم اسم النموذج الذي أبلغ عنه المشغل، ويستدعي برومبت الاستخراج والتحقق الحقيقيين في المشروع؛ لا يرسل سجل المقابلة أو إعدادات الحالة السابقة. الرسالة هنا اصطناعية للاختبار:

```powershell
$env:MODEL_PROVIDER='ollama'; $env:MODEL_BASE_URL='http://127.0.0.1:11434/v1'; $env:MODEL_NAME='qwen3.5:4b-q4_K_M'; $env:OLLAMA_REASONING_EFFORT='none'; python scripts/diagnose_ollama_extraction.py --pending-slot narrative --message 'في شخص عم يهددني على واتساب.'
```

يطبع الأمر الزمن الكلي وزمن المزود، وإعداد التفكير، وهل كان الرد صالحًا، ونتيجة الاستخراج، والحقائق المقبولة وأسباب تصفية الحقول دون إظهار الرد الخام. `valid_empty` تعني ردًا صالحًا بلا حقائق؛ `all_facts_filtered` تعني وجود مقترحات استبعدها المدقق كلها؛ `extracted` تعني وجود حقيقة مقبولة. لا تعد الحالتان الأوليان نجاحًا للاستخراج. هذا الأمر موثق للتشغيل على Windows ولم يُنفذ في هذه البيئة على Ollama أو على جهاز المستخدم.

## مزود OpenAI-compatible خارجي

اضبط قيم المزود في عملية التطبيق نفسها، ولا تضع مفتاحًا حقيقيًا في Git أو ملف مشترك:

```powershell
$env:MODEL_PROVIDER = "openai-compatible"
$env:MODEL_BASE_URL = "https://your-provider.example/v1"
$env:MODEL_NAME = "<model-id-supported-by-your-endpoint>"
$env:MODEL_API_KEY = "<secret-from-your-secret-store>"
$env:MODEL_TIMEOUT_SECONDS = "60"
```

أعد تشغيل التطبيق بعد تغيير المتغيرات. لا تُعرض حالة «الخدمة متاحة» حتى ينجح فحص القائمة، ولا تُعرض «توليد ناجح» حتى ينجح الاختبار الثابت. فشل الشبكة أو المهلة أو رفض المخطط يظهر في الواجهة، ويعود استخراج الوقائع إلى القواعد المحلية أو إجابة الإرشاد المستندة إلى المصادر المحلية.

## تقييم القواعد أو النموذج على الحالات الاصطناعية

شغّل الأوامر من جذر المستودع وفي نافذة PowerShell نفسها التي تحتوي إعداد المزود. تقييم القواعد محلي ولا يستدعي نموذجًا؛ أما `--mode model` فينفّذ فحص المزود وتوليدًا ثابتًا ثم يرسل الرسائل الاصطناعية الثابتة المحددة في مجموعة الاختبار، ولا يستخدم حالات أشخاص حقيقيين. قد يستغرق ذلك عدة دقائق أو يستهلك حصة المزود الخارجي. استخدم ملف إخراج مستقلًا لكل وضع، ولا تمرر مفتاحًا ضمن الأمر أو تحفظه في Git.

```powershell
python scripts/evaluate_scenarios.py --mode rules `
  --dataset tests/evaluation_scenarios.json `
  --output reports/evaluation/rules-windows.json

python scripts/evaluate_scenarios.py --mode model `
  --dataset tests/evaluation_scenarios.json `
  --output reports/evaluation/model-windows.json
```

يفشل وضع النموذج بوضوح إذا لم يكتمل الإعداد أو لم تصل الخدمة أو لم يظهر النموذج أو فشل التوليد. يسجل JSON المزود واسم النموذج ومحاولات الاستدعاء والـJSON والمخطط المقبولين، والحقائق التي صفّاها المدقق بأسباب منفصلة، والحقائق التي وصلَت إلى الدمج وما تجاوزه أو صححه، والرجوع وزمن الاستجابة. تعريف الاستخراج في الإصدار 5 يستثني حقول السلامة/القرار مثل `direct_danger` التي يديرها المحرك؛ توقعات مجموعة الاختبار الأصلية تبقى ثابتة للمسار المتكامل. لا يحتسب نجاح الرجوع المحلي نجاحًا للاستخراج. استخدم فقط المجموعة الاصطناعية الثابتة إلى أن تتوفر موافقة وحوكمة واختبارات بيانات مناسبة.

### تقييم المحادثة العربية v2

الأداة التالية مستقلة عن تقييم السيناريوهات القديم، وتشغّل القواعد أو النموذج على مجموعات المحادثة الاصطناعية `acceptance`, `development`, و`holdout`. وضع القواعد لا يستدعي مزودًا. وضع النموذج يجري فحص الإعداد/الخدمة/النموذج أولًا، ثم يحسب استخراج النموذج ودمج API والرجوع والزمن كلًا على حدة؛ fallback لا يُسجَّل نجاحًا للنموذج. إرسال السياق السابق من CLI متوقف افتراضيًا حتى في وضع النموذج؛ أضف `--include-bounded-context` فقط إذا أردت إجراء هذا الجزء من التقييم الاصطناعي.

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate_conversation_v2 `
  --mode rules --suite both `
  --output reports/evaluation/conversation-v2-rules-windows.json

.\.venv\Scripts\python.exe -m scripts.evaluate_conversation_v2 `
  --mode model --suite both --timeout 120 --include-bounded-context `
  --output reports/evaluation/conversation-v2-model-windows.json
```

مجموعة `both` تشغّل ثلاث مجموعات اصطناعية ثابتة فقط، ولا ترسل بيانات حالة مستخدم. إذا لم يكن المزود مضبوطًا أو لا يمكن الوصول إليه، تسجّل الأداة `status: not_run` وملفًا بلا نتائج نموذج بدل اختلاق نتيجة.

### تجربة يدوية من المتصفح باستخدام مزود فعلي على Windows

هذه خطوات smoke test يدوية للمشغل وليست اختبارًا أُجري على جهاز Windows للمستخدم. استخدم مزودًا تملك حق استعماله، واحصل على عنوان API واسم نموذج مدعومين منه. لا تحفظ المفتاح في المستودع أو في أمر مكتوب حرفيًا؛ حمّله من مخزن الأسرار إلى بيئة عملية PowerShell الحالية. لموائم Ollama المحلي، اتبع القسم السابق ولا تضع مفتاحًا.

1. اضبط متغيرات `MODEL_PROVIDER`, `MODEL_BASE_URL`, `MODEL_NAME`، و`MODEL_API_KEY` (للمزود الخارجي فقط) في جلسة PowerShell نفسها التي ستشغّل منها التطبيق، ثم أعد تشغيل التطبيق:

```powershell
Set-Location C:\path\to\accp-ai
.\.venv\Scripts\Activate.ps1
# حمّل MODEL_API_KEY من مخزن الأسرار؛ لا تكتب القيمة هنا ولا تحفظها في ملف مشترك.
$env:MODEL_PROVIDER = "openai-compatible"
$env:MODEL_BASE_URL = "https://your-provider.example/v1"
$env:MODEL_NAME = "<model-id-supported-by-your-endpoint>"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

2. افتح `http://127.0.0.1:8000` في المتصفح، واضغط **فحص الإعداد والخدمة والنموذج** ثم **اختبار توليد ثابت**. الأول يفحص الاتصال والقائمة دون إرسال نص الحالة؛ والثاني يرسل JSON ثابتًا لا يحوي بيانات الحالة. لا تتابع إلى إرسال حالة إذا كانت أي مرحلة غير ناجحة.
3. ابدأ حالة تجريبية جديدة واكتب نصًا اصطناعيًا لا يخص شخصًا حقيقيًا، مثل: `ظهر حساب مزيف على إنستغرام`؛ عند ظهور مربع الموافقة، الموافقة الأولى تسمح بإرسال **نص الرسالة الحالية فقط** لهذا الإرسال. إذا احتاج النموذج مرجعًا سابقًا، فعّل مربع الموافقة الثاني الاختياري المنفصل لإرسال حتى أربع عناصر رسائل حديثة (منها السؤال المعلّق) وعشر حقائق وأربعة أحداث مالية ذات صلة بحد 4500 حرف. كلا المربعين غير محددين افتراضيًا ويُعاد ضبطهما لكل رسالة. لا يُرسل سجل المحادثة الكامل أو رمز الجلسة. لا تختبر بأسماء أو أرقام أو صور أو إفادات شخصية.
4. تحقق من لوحة **مسار التشغيل الفعلي**: يجب أن يظهر اسم المزود/النموذج المستخدم، زمن الاستجابة، وهل قُبلت النتيجة كليًا أو جرى استبعاد حقول بعينها. عند فشل المزود أو المخطط يجب أن تظهر العودة إلى القواعد. قبول الاستجابة لا يعني صحة كل اقتراح؛ التفصيل يخص بيانات التقييم الاصطناعي، أما الواجهة فتعرض فقط عدد/أسماء الحقول المفلترة دون اقتباسها.
5. أكمل الحوار الاصطناعي وراجع الملخص، ثم جرّب تنزيل JSON والطباعة. لا تخلط هذا الفحص اليدوي مع أمر التقييم `--mode model` أعلاه: الأخير يشغّل المجموعة الاصطناعية الثابتة ويكتب JSON منفصلًا.

اختبارات Chromium الآلية المتوفرة تُشغّل محليًا بـ `python -m unittest discover -s tests -p 'test_browser.py' -v`، لكن mocks لوحة الاتصال فيها **لا تتصل بمزود فعلي**؛ هي تتحقق من عرض الحالات والسلوك. خطوات الفقرة أعلاه هي تجربة مزود حقيقي يدويًا، ولم تُنفذ على جهاز Windows للمستخدم.

## حدود الإرسال والموافقة

فحص الحالة غير التوليدي لا يرسل محتوى الحالة. واختبار التوليد يستخدم سؤالًا ثابتًا. أما استخراج الوقائع فيتطلب موافقة لكل طلب على نص الرسالة الحالية؛ وإرسال السياق السابق يتطلب مربع موافقة اختياريًا منفصلًا، ويظل محدودًا كما سبق. لا يُرسل سجل الجلسة الكامل أو معرّف الجلسة أو الرمز. يرسل مسار السؤال الإرشادي الحالي ومقتطفات المصادر المختارة فقط عند الموافقة عليه، ولا يعتبر موافقة استخراج الوقائع إذنًا بإرسال السؤال أو السياق. إذا كتب المستخدم سؤالًا واضحًا في وضع المقابلة، يجيبه التطبيق محليًا عند ملاءمة المصدر ويستأنف السؤال المعلّق.

المخرجات لا تحل محل القواعد: الاقتباسات يجب أن تطابق نص المصدر حرفيًا، وحقائق النموذج يجب أن تحمل اقتباسًا حرفيًا من الرسالة الحالية وأن تجتاز المخطط والتحقق المحلي. لا يُحوّل نجاح الاختبار الثابت إلى ادعاء بصحة فرز أو بنصيحة قانونية.
